# LocalVNC 使用说明

## 界面与 SSH

- Windows 使用自定义顶部栏：右上方最小化、最大化／还原、关闭；拖动顶部空白区域移动窗口，双击空白区域切换最大化。窗口边缘仍可调整大小。
- VNC 连接成功后，点击画面，或聚焦暂停遮罩后按 Enter／空格接管键鼠。程序失焦或隐藏时，会释放已按下的键和鼠标按钮并暂停远程输入，连接和画面更新继续保留。重新聚焦窗口不会自动接管；确认动作完整释放后才恢复控制，确认键和第一次点击不发送到远端。在程序内点击工具栏、切换 SSH 或编辑表单会释放残留按键与鼠标，但保留接管状态；本地输入保持本地焦点，返回画面后的第一次点击直接操作远端。显式只读设置始终优先。
- 画面工具栏的键盘按钮展开下方的玻璃质感虚拟键盘，不再发送 Ctrl+Alt+Del（Ubuntu 可能将它映射为注销）。支持字母、数字、功能键、方向键及组合键；先点 Ctrl / Alt / Shift / Win，再点目标键，修饰键随该次按键自动释放。Caps 只控制虚拟键盘字母大小写。失焦、只读或断开后禁用输入并清除锁定状态，恢复控制仍须点击画面或聚焦遮罩确认。全屏时也可展开、收起键盘。
- 输入释放适配器针对固定的 noVNC 1.6.0：它没有公开的完整输入释放 API，单独设置 `viewOnly` 会过滤释放按键。升级 noVNC 时必须验证适配器和回归测试；检测到版本或内部接口变化时保持远程输入禁用。
- 顶部分类仅筛选列表，不中断已打开的 VNC 或 SSH。选择另一个服务器会切换 VNC 目标，已连接的 SSH 继续保留原目标；右栏底部始终显示该 SSH 会话地址。
- 使用左栏 `+` 添加服务器，底部“编辑服务器”修改当前条目。编辑表单在弹窗里，取消新增不会断开已有会话；新增时不显示只对已有条目有效的“清除密码”和“新增”。删除服务器会同时移除已保存的密码，须在确认框中确认，默认焦点在“取消”。分类和两侧面板的显隐状态会保存。
- SSH 使用 Windows 自带的 OpenSSH 客户端与 ConPTY，前端使用 [xterm.js](https://xtermjs.org/)。需要 Windows 10 1809 或更新版本，以及 Windows“可选功能”中的 OpenSSH 客户端。
- 右栏独立填写主机、端口和用户名。初始主机从当前服务器推导，PVE 默认指向 **PVE 宿主机**；连接虚拟机内的 SSH 时需要手动填写虚拟机地址。SSH 用户名独立于 PVE 的 `root@pam`，默认 `root`。
- 点击连接后，在终端内确认主机指纹并输入密码，密码不会显示字符；密钥和 SSH 别名沿用本机 OpenSSH 配置。地址、端口和用户名可随服务器保存，SSH 密码不交给应用保存。主机指纹由 OpenSSH 的 `known_hosts` 管理。
- 收起右栏不会断开 SSH，展开后终端会重新适配尺寸。右栏“断开”只结束 SSH，中央“断开”只结束 VNC；关闭应用会清理 SSH 子进程。
- 终端支持交互输入、Ctrl+C、粘贴和尺寸调整，输入及输出队列有上限。文本按 UTF-8 编码，xterm `onBinary` 的鼠标报告保留原始字节，两者串行发送。输出在 xterm 解析完成后确认，形成背压；不加载远端页面、不处理终端请求的剪贴板写入。

## 连接与保存

- PVE 使用 HTTPS，默认验证证书。自签名环境可在具体服务器条目里明确勾选“跳过证书验证（不安全）”；该选择同时作用于 API 和 WSS，不会扩散到其他服务器。旧配置的全局 `insecure` 不自动沿用，需要逐个确认。当前尚未提供证书指纹固定。
- 私有 PVE CA 可按端点放到 `Documents/localVNC/pve-ca/<SHA256(规范化 HTTPS origin)>.pem`。文件必须是单张有效 PEM 证书，最多 64 KiB；API 与 WSS 使用同一次读取的 CA，保留证书链、有效期和主机名校验，其他端点及 Windows 全局信任不受影响。没有文件时使用系统信任，文件损坏时明确报错；每次连接重新读取，移除该文件可撤销此端点的额外信任。安装前必须通过独立可信通道核对 CA 指纹。
- 直连支持 RFB 3.3、3.7、3.8 和 macOS 的 3.889。用户名留空时沿用传统 VNC 流程，默认优先 VeNCrypt/TLSVnc；若提供 VeNCrypt 却没有 TLSVnc，连接会报错，不会自动降级。
- VNC 直连先协商服务器的认证类型，再请求所需凭据：VNCAuth 只显示密码，macOS 的 DH/Apple Remote Desktop（ARD）显示用户名与密码，无认证服务直接连接。非 TLS 认证按服务器提供的顺序选择支持的类型；“优先 TLS”和“必须 TLS”仍按原策略执行，不因新增 ARD 绕过。
- macOS 账户认证填写 Mac 账户的短名称和登录密码，不需要先配置用户名或选择操作系统。“编辑服务器 → 预设 VNC 用户名”只用于自动填充；右栏 SSH 用户名独立设置。勾选记住后，用户名在认证成功时保存到配置，密码另存 Windows 凭据管理器；换账户时轮换凭据标识，保留已连接的画面。
- ARD 的 DH/AES 凭据交换由固定版本的 [noVNC 1.6.0](https://github.com/novnc/noVNC/blob/v1.6.0/core/rfb.js) 完成，后端只桥接协议字节。ARD 不提供 TLS 画面传输或服务器身份验证，不能满足“必须使用 TLSVnc”策略。账户用户名和密码超过 63 个 UTF-8 字节或含空字符时直接提示，避免被协议截断。
- 已保存的密码仅在服务器实际请求匹配的凭据后读取，账户密码和传统 VNC 密码不混用。补充认证、取消、重复请求和延迟凭据读取仍绑定当前会话。用户名保存失败时保留已认证的连接，不把密码记到旧账户；不勾选记住时不保存本次用户名和密码。
- TLSVnc 使用匿名 TLS，不能验证远端身份；握手与记录层使用静态链接的 OpenSSL，兼容范围仍限定为 TLS 1.2/P-256/AECDH-AES256-SHA，不能等同于 TigerVNC 的完整 GnuTLS 支持范围。允许匿名套件所需的低安全级别只用于此专用 context，不影响 PVE 的证书验证；完整性或协议校验失败会终止连接，不自动重连或降级。
- 密码仅在当前会话认证成功后保存。保存失败不影响本次连接。修改服务器地址、类型、VNC 用户名或 PVE 身份/目标会更换凭据标识，需要重新输入密码；单独改名称会保留原标识。
- 凭据写入、清除和配置绑定变更使用同一后端顺序边界；清除会撤销旧会话的保存代次，删除成功后迟到的旧写入不能重建该条目。空密码作为明确的空值保存，只有显式“清除密码”执行删除。改名或无变化保存保留 VNC；连接参数或安全策略改变才重建连接。
- 保存的密码被明确拒绝后，可点击“重新输入密码”开始新会话；新密码认证成功且勾选记住后才替换旧值。证书、权限、网络和不兼容的安全类型不当作密码错误；认证重试受限会单独提示。
- 建立连接到收到完整 RFB `connect` 的截止时间为 60 秒，包含后端预备与认证、ServerInit 等阶段。等待用户填写密码时暂停计时，提交后重新计时；成功连接后取消，不因静止桌面断开。
- 已连接的 VNC 直连遇到传输中断后，按 1／2／3／5／8 秒间隔自动重连，总恢复时限 60 秒；恢复并稳定 10 秒后重置退避。等待与握手阶段均可取消，切换服务器或关闭窗口会取消恢复。首次连接失败、PVE、密码错误、认证限速、TLS 握手和协议错误仍需手动处理。恢复不会接管键鼠，也不影响 SSH；未保存的密码不会从旧连接重放，重新提示认证时结束后台重连。实现依据、验证范围及 Ubuntu 会话切换的诊断见 [会话恢复说明](vnc-session-recovery.md)。
- 上游直连 TCP 启用 keepalive（空闲 15 秒、间隔 5 秒、3 次探测），不向 RFB 插入自定义心跳，不以画面静止判定断线。60 秒恢复预算从检测到故障后开始；实际丢包检测时延由 Windows TCP 与网络决定，尚未验证所有网络的时间上限。
- 编辑／删除服务器与 SSH 配置保存先提交候选配置，成功后才更新内存；旧凭据最后清理。保存失败保留旧条目和编辑草稿，凭据清理失败单独提示。保存期间的选择和设置修改按同一队列写入，不用旧列表覆盖已提交条目。
- PVE 地址允许省略 HTTPS 协议，新编辑保存时规范化；SSH 默认主机使用相同的解析规则，支持带方括号的 IPv6。搜索和普通界面刷新不查询凭据，存在性查询也不复制或解码密码。
- 配置采用 `schemaVersion: 1`，兼容原有 PVE/direct 条目和旧式直连地址。损坏或未知类型会阻止自动保存，并保留原文件。
- 保存会先写入并同步唯一临时文件，使用 Windows 同目录替换，保留上一完整版本 `config.json.bak`。同一配置仅允许一个应用实例持有写锁；检测到外部修改后停止覆盖。异常后先关闭应用、另存原文件，再检查备份恢复。没有进行断电故障验证。
- 本机桥接仅监听 `127.0.0.1`，每会话使用随机令牌并校验 WebSocket Origin；半开握手有超时和数量限制。连接切换、取消、错误均按会话标识处理。
