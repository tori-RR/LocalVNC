# VNC 直连的会话恢复

VNC 服务重启、图形会话切换或网络中断后，原 TCP 连接可能失效。LocalVNC 在已连接的 VNC 直连中检测到可恢复的传输错误时，会尝试建立新连接。

## 恢复流程

- 仅在成功连接过的 VNC 直连遇到传输中断后启动；首次连接失败和 PVE 不启动后台恢复。
- 第一次等待 1 秒，后续依次等待 2、3、5、8 秒，此后保持 8 秒。一个恢复过程的等待及建立连接合计最多 60 秒。
- 短暂连上又掉线不会重置这个时限；连续稳定 10 秒才重置。达到总时限时，已恢复的连接保留；仍在等待或握手的连接结束，并显示手动重试入口。
- 每次重连重新预留后端会话，沿用同一目标与安全策略。取消、切换目标、编辑连接目标及关闭窗口清除计时器，过期回调只能清理自己预留的会话。
- 认证失败、认证限速、不支持的认证类型、TLS 握手失败、无效地址及协议错误停止恢复，保留明确的错误提示。后端把协商时 TCP EOF 与真实协议错误分开报告。
- 已保存的 VNC 凭据只有在新服务器请求匹配认证类型时才读取。未保存的密码不从旧会话重放；显示认证对话框时结束后台恢复，保留正常的用户输入与认证超时流程。Ubuntu 的系统登录密码仍由远程登录界面处理。
- 每个新画面从暂停控制开始，需要点击画面或使用现有键盘接管入口；不重放键鼠事件、不自动操作登录界面。VNC 取消和重连不调用 SSH 断开接口。
- 服务器主动改变分辨率沿用 noVNC 的 DesktopSize 支持；保持 `resizeSession = false`，不请求改变远程系统的分辨率。

## 隔离验证

回归测试位于 `tests/reconnect.test.cjs`。浏览器复验可在仓库根目录运行 `node tests/vnc-browser-fixture.cjs`，访问输出的 `WORKSPACE_URL`，追加 `?mode=direct&handoff=2&resize=1`，然后点击连接。

测试服务会终止前两个合成 RFB 连接，在最后一个连接发送 DesktopSize。验证重连后仍暂停输入、分辨率更新正确，以及取消和目标切换能终止恢复。这些选项仅用于回环测试，不操作真实远程主机。

TCP keepalive 的空闲时间为 15 秒、探测间隔为 5 秒、探测次数为 3。实际故障检测时延取决于系统 TCP 实现和网络环境；60 秒恢复预算从检测到故障时开始。复现真实断线时，应结合服务端日志区分网络故障、图形会话退出和 VNC 服务重启。
